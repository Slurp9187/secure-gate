HOW TO READ 'strawman: BUILD FAILED (gen)' IN THE FIRST BLOCK
  That line is a HARNESS DEFECT, not a result. The probe's Cargo.toml was
  written into the strawman library's directory and clobbered it, so the
  profile-generation build had no library to build. It says nothing about any
  allocator. The second block is that same configuration re-run correctly,
  which is why the second block exists.

WHY 'same=true' ON EVERY ROW IS LOAD-BEARING
  same=true means the same block came back: the allocator handed back the
  block that was just freed, so the bytes read are the bytes that were in it.
  A hits=0 with same=false would mean a DIFFERENT block was read and would
  prove nothing. Every row below is same=true, in both blocks.

WHAT THIS RUN DOES AND DOES NOT SHOW
  It shows that under this configuration the planted pattern was recovered
  from a freed block with no allocator installed (16/16) and from the
  synthetic fn-pointer construct (16/16), and was not recovered from either
  zeroizing-alloc 0.1.1 or secure-gate-zalloc (0/16, both block sizes).
  The synthetic construct is a control for the measurement. Its behaviour is a
  property of that construct alone and says nothing about any released crate.
